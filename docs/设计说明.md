# 青禾校园论坛：实现约定

本项目采用 Django 5.2、MySQL 8.0 和原生中文页面。浏览器及 JMeter 经过同一套 Session 登录、CSRF 校验和业务处理。Waitress 监听 127.0.0.1:8000，8 个工作线程。数据库连接本机已有MySQL（默认127.0.0.1:3306），不修改其全局设置。数据库方案已按用户要求由PostgreSQL切换为MySQL。

## 视觉方案

主体色为校园蓝绿 #116d73、正文 #203d46、辅助文字 #667e86、纸面 #f5f8fa、浅蓝绿 #e9f3f3、便笺黄 #dec786。正文使用本机微软雅黑，留言板标题使用楷体。首页左侧是最新讨论，右侧是社区约定；上方两张校园便笺是唯一主要装饰，不引入外部字体或图片请求。

## 数据规则

- 用户名唯一，密码由Django加盐哈希保存；昵称、简介不参与身份识别。
- 热门按点赞数、未删除评论数、发布时间依次降序；最新按发布时间与ID降序。
- 评论允许回复，但页面统一两层展示，保留被回复作者。回复对象必须属于当前帖子。
- 删除评论清空正文并保留占位和回复；删除帖子先解除内部评论引用，再删除关联评论和点赞。
- 普通用户只可编辑删除本人内容，写操作必须登录并通过CSRF校验。
- 点赞接口使用明确的like/unlike操作；重复提交同一动作不会反复切换状态。数据库对用户与帖子建立唯一约束。
- 第一版不实现账号注销、文件上传、私信或真实学籍认证。

## 表与索引

User：用户名、哈希密码、昵称、简介和Django内置权限字段。
Category：唯一名称、唯一slug、排序。
Post：作者外键、分类外键、100字标题、10000字正文和时间；创建时间、分类及时间索引。
Comment：帖子外键、作者外键、自关联parent、1000字正文、时间、删除标记；帖子及时间索引。
PostLike：用户外键、帖子外键、时间；用户与帖子组合唯一。
Session及权限表由Django维护。实际迁移文件保存在forum/migrations。

## 环境和数据隔离

.runtime存放本地秘密配置与演示账号，均排除出源码版本控制，不要公开分享。qinghe_forum_app是专用非管理员账号，仅有qinghe_forum、qinghe_forum_perf和test_qinghe_forum三个命名空间的权限，无全局管理权限。管理员密码由用户在本机交互输入，不保存。本项目当前仅限本机教学使用。

性能测试必须使用独立的qinghe_forum_perf库，不能直接对演示库清库。任何清理或重置必须明确目标，先说明并确认。功能测试由Django自动创建、销毁test_qinghe_forum，不修改演示库。

MySQL数据库采用utf8mb4和区分大小写/重音的utf8mb4_0900_as_cs排序规则，保持用户名唯一性规则明确。存储引擎使用InnoDB，连接开启严格模式，隔离级别为READ COMMITTED。Django迁移通过ORM生成，可直接用于MySQL。业务测试需要重新在MySQL执行，不能沿用PostgreSQL的结果。

旧PostgreSQL实例已停止，下载包和旧数据目录保留；旧setup_local.py禁止再次初始化或启动，只保留停止/状态检查入口。

## 测试状态

本文件描述设计，不代表测试通过。执行结果单独保存在test-results及docs中的阶段报告。超过100用户的压力测试必须展示具体参数，获得再次确认后执行。
