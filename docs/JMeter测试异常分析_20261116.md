# JMeter帖子浏览75用户异常分析

当前状态：按用户要求暂停测试。没有恢复网站、启动新负载或执行压力测试。日期为2026年11月16日，以下时间均为北京时间。

## 原因与影响

本轮75条请求全部连接被拒绝，没有进入网站。原因是旧版监控程序从准备时刻开始计算固定900秒期限；等待用户操作界面的时间耗尽期限后，程序关闭了自己启动的8001独立测试网站。JMeter在数小时后才开始运行，启动前没有重新检查网站服务，这是测试执行流程的疏漏。

因此，本轮属于测试准备失效，不能据此判断网站或MySQL无法承受75并发。线程遇到失败后立即停止，也没有形成75用户共同持续运行。附带的“缺少业务标识”断言失败来自没有收到网站页面，并非已经证实的页面内容错误。

## 已作修正及验证范围

1. 监控等待与正式运行计时分开：检测到第一个线程启动后，再计算Ramp-up和稳定运行期限。准备等待仍有限时，超时后必须重新准备。
2. `gui_observer.py`发布就绪、运行、关闭状态及每秒状态更新时间，并检查自己启动的网站进程是否存活。启动时增加一次健康检查。
3. 新增`performance/check_gui_ready.py`：点击GUI开始前，核对状态不超过5秒、监控和网站进程身份、独立数据库配置与本机8001健康检查。过期、停止或错误环境均拒绝开始。该检查不启动网站或并发负载，不能阻止用户绕过检查直接点击GUI。
4. 持续资源超限时，监控中止本轮并关闭自己启动的独立测试网站，以降低负载；保留中止证据，不将其算作通过。它不会关闭共享MySQL或操作其他网站进程。

验证：两个修改文件通过Python语法解析；在已关闭状态运行启动前检查，正确返回`ready: false`并以非零状态退出。该拒绝路径不发送网站请求。没有重跑功能测试或JMeter负载；修复后的完整GUI流程仍为**未验证**。
